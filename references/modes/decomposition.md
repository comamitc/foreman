# Decomposition

Load this file only when a complete published initial plan for the admitted revision proposes a decomposition in its [plan](../../templates/plan.md) ("## Decomposition") section.

This file owns decomposition filing. [planning](../planning.md) ("proposes a decomposition only when") owns when a plan proposes one.

## Procedure

1. **Filing.** [one-pass planning](../plan-convergence.md) ("before any `capstan:plan-review` projection") owns when filing starts. The coordinator files with no host-session question: one issue per missing child of the filing plan (step 4), in the parent's repository, in topological order of the Depends on cells, ties broken by Child key, so each prerequisite has an issue number before a dependent's body is written. Create each with `gh api repos/OWNER/REPO/issues --method POST -F title=@TITLE_FILE -F body=@BODY_FILE`. [contract](../contract.md) ("## Marked Markdown artifacts") owns body files and read-back, and ("On ambiguous exit, observe effects before retrying") owns a create that fails midway.
2. **Child body.** The title is the Title cell. The body follows [spec](../../templates/spec.md) ("# Problem") without its spec marker: the Problem names the Child key and links the parent; `## Acceptance criteria` copies the parent criteria in its Parent criteria cell from the admitted spec; `## Decisions` holds one `Depends on #M` Decisions entry per prerequisite child, M that child's issue number; Vocabulary and Out of scope copy the parent's; Open questions is empty; Original request quotes the child's plan row. The body ends with three lines: `Child: CK`, CK its Child key; `Plan: PLAN_URL`, the filing plan's comment URL; and `Parent: owner/repo#N`, the parent.
3. **Sink child.** When exactly one child depends, directly or through other children, on every other child, its `## Decisions` also holds the entry `Closes parent: #N`. [publication](../publication.md) ("`Closes parent: #P`") owns that child's pull-request line.
4. **Lookup.** Before each create, list `gh api --paginate "repos/OWNER/REPO/issues?state=all&per_page=100"`, with no time bound, and drop pull requests. Apply [security](../security.md) item 1 to each listed issue by its `author_association` before reading its body; an issue item 1 does not admit is not read and is not a child. Keep each admitted issue whose body holds the line `Parent: owner/repo#N`. The filing plan is the plan comment that the kept issues' `Plan:` lines name, or, when none is kept, the published initial plan just read back; a later plan comment does not change it, so child keys stay those of the plan that filed the first child. A kept issue whose `Child:` line names a Child key of the filing plan is that child, already filed; the coordinator files only the missing children of the filing plan. Kept issues that name two plans or repeat a Child key, and a failed or partial listing, file nothing and follow [recovery](../recovery.md) ("## Observe, diagnose, retry").
5. **Read-back.** Each source below is consumed only after [security](../security.md) item 1 ("Before consuming issue/comment text, inspect GitHub `author_association`") admits it by its `author_association`; a marker, a `Parent:` line, or a login is not trust evidence, and item 1 owns an untrusted issue or comment. The sources are: each created child, read back with `gh api repos/OWNER/REPO/issues/M` and compared with its body file; the filing plan comment a `Plan:` line names, read with `gh api repos/OWNER/REPO/issues/comments/ID`; and, on resume, the parent's marked summary, from `gh api --paginate repos/OWNER/REPO/issues/N/comments`, and each child URL it lists, read back with `gh api repos/OWNER/REPO/issues/M`. A source item 1 does not admit is not a read-back: an excluded summary is not completion, and an excluded child or plan comment follows [recovery](../recovery.md) ("## Observe, diagnose, retry").
6. **Decomposition end.** After every child of the filing plan is filed or found and read back, the parent run ends at this stop, which [SKILL.md](../../SKILL.md) ("Stop only at") lists: no commit, no pull request, the parent keeps `capstan:planning`, and it gets neither `capstan:ready-to-deploy` nor `capstan:blocked`. Record each child URL as a notes line in `ledger.md`, append the `run-end` event with outcome `decomposition end`, and publish the marked summary by [end of run](../end-of-run.md) ("Any other marked summary"), with `none` as its PR URL. The summary also lists each child URL with its `Depends on` entries; the children that can start now, those with no `Depends on` entry; that each startable child runs in its own Capstan invocation; and, with no sink child, closing the parent after its last child merges as an operator step.
7. **Resume.** On resume, the parent's marked summary that step 5 admits, with every child URL it lists read back by step 5, is completion: report its URL and stop again at the decomposition end, with no second filing. Without that summary, steps 1–6 run again, and step 4 finds the children already filed.
8. **Batch parent.** Inside a batch, a decomposed parent ends at this stop. Its children join no running batch, and the final message lists their URLs under the parent.

## Review

Block a worker filing; a filing before the initial plan is published and read back, or after a `capstan:plan-review` projection or plan-review launch; a child outside the parent's repository; a child body without its criteria, its `Depends on #M` entries, or its `Child:`, `Plan:`, or `Parent:` line; a decomposition of an issue that [planning](../planning.md) ("A plan also proposes no decomposition when") excludes; a consumed issue or comment whose `author_association` was not checked first; a parent with a commit, a pull request, `capstan:ready-to-deploy`, or `capstan:blocked`; and a second filing on resume.
