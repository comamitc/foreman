# Learn invocation

Load this file only when [contract](../contract.md) "## Read-only invocations" dispatches the `learn` keyword.

This file owns the learn invocation.

It runs from any workspace, needs no repository, and writes, files, and publishes nothing.

## Argument grammar

The invocation is `learn` followed by zero or more `repo OWNER/REPO` pairs and at most one `since YYYY-MM-DD` pair, in any order. In a `repo` pair, the second token is one repository name: an owner and a name, each non-empty and made only of letters, digits, `.`, `_`, and `-`, joined by one `/`. In a `since` pair, the second token is a calendar date written `YYYY-MM-DD`. A repeated `repo` pair names its repository once. Any other token, a pair missing its second token, a second `since` pair, or an impossible date makes the invocation text intake, as [contract](../contract.md) "## Read-only invocations" states.

Examples: `learn`; `learn since 2026-10-04`; `learn repo comamitc/aiwatch`; `learn repo a/b repo c/d since 2026-01-01`; `learn since 2024-02-29 repo a/b`. `learn what went wrong last week`, `learn since yesterday`, `learn since 2026-02-30`, `learn since 2026-10-04 since 2026-10-05`, and `learn repo` are text intake.

## Sources

- **Local.** The evidence roots are the state root and the old root [contract](../contract.md) ("## Compat read path") names, with the `FOREMAN_STATE` and `CAPSTAN_STATE` overrides it states; when both resolve to one path, it is listed once. A run is one `OWNER/REPO/N/` directory under either, where `N` is an issue number. Its sources are `ledger.md`, `events.jsonl`, and the results and logs that survive under [telemetry](../telemetry.md) "## Ledger, pile, and deletion".
- **Remote.** Marked artifacts are those whose first line starts with `<!-- foreman:` or `<!-- capstan:`. For each run: the marked `plan-review` comments and marked summaries on issue `N`; the marked `review` censuses, the review comments, and the reverts of the delivered commits of the run's marked pull request; each as [telemetry](../telemetry.md) ("This section owns earlier deliveries") reads them. The marked pull request is the one matching the PR identity [contract](../contract.md) states in its stable identity table ("exact head `foreman/N` and body line `Foreman: owner/repo#N`"), or its compat form.
- **Foreman repository.** `comamitc/foreman`, whose open issues Procedure step 9 lists for deduplication. It is named here, not inferred from the installed package.

`repo` and `since` pairs narrow only which runs are analyzed; every source of a run in scope is read.

## Procedure

The coordinator does every read and all grouping in the invoking session, under the rules [contract](../contract.md) "## Read-only invocations" states, for every repository it reads, including `comamitc/foreman`. This file's stricter rules: the procedure runs only file reads, directory listings, and `gh api --method GET` calls; it runs no other `gh` command, no `git` command, and no worker; it writes no file, including a temporary file; and it prints the report only in the invoking session. Filing a proposal follows [improvement](improvement.md) ("An issue is published only after an explicit improvement invocation").

1. **Parse.** Split the trimmed invocation into tokens. Collect the `repo` names, in first-seen order, and the `since` date, if any.
2. **Root.** Resolve both evidence roots "## Sources" names. A root that does not exist or cannot be listed is recorded under `Limitations:` and Coverage `Gaps:` with its error and gives no run; the other root is still listed. With neither root listed, find no run and continue at step 11.
3. **Runs.** List every `OWNER/REPO/N/` directory under each listed root. A run is one `OWNER/REPO/N`: when both roots hold it, the new root's directory is the run, and the old root's directory is listed under Coverage `Not read:` with the reason `superseded by the new root`. A directory at that depth whose last name is not a number is listed under Coverage `Not read:` with that reason. With `repo` names, keep only runs of those repositories; the runs of other repositories are counted under Coverage `Not read:` with the reason `outside repo filter`, by repository, and a named repository with no run is recorded for the `No local runs:` line, with nothing read for it. With no run kept, continue at step 11.
4. **Window.** Without `since`, every run kept is in scope, and this step reads nothing. With `since`, date each kept run with only these reads. Read its `ledger.md` and `events.jsonl`, where they exist, for its start: the time of its `run-start` event in `events.jsonl`, else the budget start `ledger.md` records, which [telemetry](../telemetry.md) names ("budget start"), else none. A date the ledger quotes elsewhere is not a run start. a run whose start is on or after the date is in scope. For any other run, make the issue-comment, pull-request, and pull-request issue-comment reads step 6 names, only as far as needed to find the creation dates of its marked artifacts, using only artifacts that pass [security](../security.md) item 1 ("inspect GitHub `author_association`"); a run with a marked artifact created on or after the date is in scope. Every other run is excluded, with the reason `before since`, or `undated` when it has no start and no dated marked artifact. An excluded run gives no occurrence; it is listed under Coverage `Excluded by since:` with its reason and every source this step read for it, and its other sources are listed under `Not read:`. A failed read here is a gap, as step 6 states. A run in scope reuses what this step read.
5. **Local reads.** For each run in scope, read `ledger.md` and `events.jsonl` in full where they exist, and record each source "## Sources" names that is absent. Read a result or log in full when the run's ledger or events cite it; list the rest under Coverage `Not read:`, counted per run. A ledger written before the attempt-table shape is read as [improvement](improvement.md) ("Ledgers written before the attempt-table shape") states. A ledger without the usage notes [telemetry](../telemetry.md) names ("The ledger notes keep the raw usage") records missing usage.
6. **Remote reads.** For each run in scope, with `gh api --method GET <path> --paginate`, reusing every response step 4 already read:
   - `repos/OWNER/REPO/issues/N/comments`, for the marked `plan-review` comments and marked summaries;
   - `repos/OWNER/REPO/pulls?state=all&head=OWNER:foreman/N` and `repos/OWNER/REPO/pulls?state=all&head=OWNER:capstan/N`, for the marked pull request `P`, keeping only the one whose body carries the identity line "## Sources" names, with its `merged_at`, `merge_commit_sha`, and base branch;
   - with `P`: `repos/OWNER/REPO/issues/P/comments` for marked `review` censuses; `repos/OWNER/REPO/pulls/P/comments` and `repos/OWNER/REPO/pulls/P/reviews` for review comments; and `repos/OWNER/REPO/pulls/P/commits` for its commits;
   - when `P` merged: `repos/OWNER/REPO/commits?sha=<base branch>&since=<merged_at>` for later commits on the base. P's delivered commits are the SHAs from `pulls/P/commits` plus its `merge_commit_sha`, the merge or squash commit on the base. A later commit whose message carries `This reverts commit <SHA>` is a revert of a delivered commit when that SHA is one of them, or when `repos/OWNER/REPO/commits/<SHA>/pulls` lists `P`, as for a rebased commit.

   Apply [security](../security.md) item 1 ("inspect GitHub `author_association`") to every comment and review before reading its text. One that item excludes, or whose trust it leaves unresolved, gives no occurrence and no date; it is counted under Coverage `Not read:` and under `Limitations:` as `trust unresolved`, by repository. A failed, truncated, or partial read is a gap for that run and source, with its error; the run's local sources still count. A repository whose every read failed is named unreadable under `Limitations:`.
7. **Occurrences and classes.** From the runs in scope, record each mistake and friction occurrence of the kinds [telemetry](../telemetry.md) ("This section owns earlier deliveries") defines, each with its repository, its run, and its citation: a `path:line` under the evidence root, or a URL plus the commit SHA the artifact records, else the marked pull request's head SHA, else the missing SHA named as a gap. Pool every repository's occurrences and group them once by that section's class rule, so that one class can span repositories. For each class, count the deliveries and the repositories it spans. An occurrence in no class is counted as a one-off and gets no proposal. A kind that no run in scope retains is a named limitation, as that section states.
8. **Partition.** Split the classes by the separation [improvement](improvement.md) ("Separate Foreman-process improvements from target-product learning") owns. A Foreman-process class gets a proposal. A target-product class is listed as a learning, with no proposal, Rule, severity, or rank.
9. **Proposals and deduplication.** For each Foreman-process class, write one proposal that meets [improvement](improvement.md) ("A proposal cites run identities"). With at least one proposal, list the open issues of `comamitc/foreman` with `gh api --method GET "repos/comamitc/foreman/issues?state=open&per_page=100" --paginate`, dropping pull requests, and apply [security](../security.md) item 1 ("inspect GitHub `author_association`") to each listed issue before reading its title or body; an issue whose trust that item leaves unresolved is not used and is named under `Limitations:` as `trust unresolved` with its URL. Deduplicate each proposal against the remaining issues as [improvement](improvement.md) ("Deduplicate against open issues") states. An open issue that already covers a proposal is named on its `Covered by:` line, and the proposal stays in the report. A failed listing is a gap, and every proposal's line reads `Covered by: not checked`. With no proposal, nothing is listed.
10. **Rank.** Give each proposal a severity from [review-convergence](../review-convergence.md) "Use this calibration in every code-review brief". Order proposals by severity, highest first, then by deliveries spanned, then by repositories spanned, most first.
11. **Redact and print.** Apply [security](../security.md) item 6 ("redact known credential values") to the whole report before printing it. Print the report under "## Report" once, then stop.

## Finding sources

Report only these rows. Each row's owner states the rule; this file names it and does not restate it. A proposal's Rule is its row's owner file and quoted anchor. A row's Graded cell names its subjects only. The procedure invents no other finding source.

| Row | Owner and anchor | Graded |
|---|---|---|
| Mistake class | [telemetry](../telemetry.md) "## Earlier deliveries and recurrence" ("Mistakes:") | the mistake occurrences of every run in scope, pooled across repositories |
| Friction class | [telemetry](../telemetry.md) "## Earlier deliveries and recurrence" ("Friction:") | the friction occurrences of every run in scope, pooled across repositories |

## Report

- Every outcome prints every block below, in this order, including a missing evidence root, no run in scope, and a named repository with no run. A block with nothing to list prints its `none` form.
- The first line is `Foreman learn — <state root>; <old root>`, then `Filter: repositories <all | names>; since <date | none>`.
- Then `Runs:` and one line per repository with a run kept at step 3: `OWNER/REPO: <in scope> in scope of <found> found; <n> read in full, <n> sampled, <n> with no readable source; <n> excluded by since`. With none, `Runs: none`. With `repo` names, then `No local runs:` and each named repository with no run, or `No local runs: none`.
- Then `Classes: <n> Foreman-process, <n> target-product; one-off occurrences: <n>`, or, with no run in scope, `Classes: none; no run in scope.`
- Then one blank line and the proposals in rank order. Each starts `N. [<severity>] <title> — <d> deliveries, <r> repositories` and holds the five fields [contract](../contract.md) "## Read-only invocations" names, in its order, then `Covered by: <issue URL>`, `Covered by: none found`, or `Covered by: not checked`. Evidence lists every occurrence's citation. The Issue body is a fenced block addressed to `comamitc/foreman`. With no Foreman-process class, the line `No proposals.`
- Then `Target-product learnings:` and one line per target-product class: its title, its repositories, and every occurrence's citation. With none, `Target-product learnings: none.`
- Then `Limitations:` and one line each: each missing evidence root, as one `no evidence root at <path>` line per root, followed by `; nothing read` only when neither root was listed; each run whose pile was deleted or that lacks a source "## Sources" names; each ledger written before the attempt-table shape; each repository or comment that could not be read; `trust unresolved:` with each repository's count of comments and reviews and each open issue's URL; each run with missing usage; and each kind that no run in scope retains. A limitation is never written as zero. With none, `Limitations: none.`
- Then `Nothing was filed or published. To file a proposal, start an improvement invocation (references/modes/improvement.md).`
- The last block starts `Coverage:` and holds `Read in full:` with each run and the sources read in full; `Sampled:` with each run whose results or logs were read only where cited; `Excluded by since:` with each run step 4 excluded, its reason, and each source step 4 read for it; `Not read:` with each source never read, including the other sources of each excluded run, each uncited result or log, each non-numeric directory, the runs outside the `repo` filter counted by repository, and the comments and reviews excluded by trust counted by repository; and `Gaps:` with each failed, truncated, or partial read and its error, a missing evidence root among them. Each sub-block with nothing to list reads `none`.

## Review

A proposal whose Rule is not a row in "## Finding sources" blocks; a Mistake class or Friction class proposal whose occurrences cite any source "## Sources" names is admitted. A target-product learning listed apart, a limitation, a one-off count, an `Excluded by since:` entry, and a proposal with a `Covered by:` line, including `Covered by: not checked`, are admitted. A report with a missing evidence root, no run in scope, or a named repository with no run that prints every block, each empty one in its `none` form, is admitted. A class rule, a kind, the proposal rule, the separation, the deduplication rule, the publication rule, the read-only rules, the evidence root path, the trust rule, the redaction rule, or the severity scale restated in this file instead of named by owner and anchor blocks, including a Graded cell that repeats its owner's rule. Classes grouped per repository instead of pooled, or a class without its repository count, blocks. A target-product learning given a proposal, Rule, severity, or rank blocks. A proposal without a `Covered by:` line blocks. Comment, review, or issue text used for an occurrence, a date, or deduplication without [security](../security.md) item 1 applied first, or text whose trust is unresolved and not named `trust unresolved` under `Limitations:`, blocks. A revert check that compares only `pulls/P/commits`, without P's `merge_commit_sha` and the `commits/<SHA>/pulls` lookup, blocks. A run excluded by `since` listed only under `Not read:`, an excluded run missing from `Excluded by since:`, a source read at step 4 missing from that entry, or an occurrence taken from an excluded run blocks. A deleted pile, a ledger written before the attempt-table shape, an unreadable repository or comment, missing usage, or a missing evidence root reported as zero or left out of `Limitations:` blocks. A run directory under the root missing from both `Runs:` and Coverage, or a marked artifact kind "## Sources" names that is neither read nor a gap, blocks. A named repository with no run that is read, given an invented result, or missing from `No local runs:` blocks. A report, including an empty one, that lacks its first line, `Filter:`, `Runs:`, `Classes:`, `Target-product learnings:`, `Limitations:`, the nothing-filed line, or `Coverage:` blocks. A learn run that runs a `gh` call other than `gh api --method GET`, runs a `git` command, starts a worker, writes a file, or creates or changes a label, issue, comment, pull request, branch, worktree, or evidence file in any repository blocks.
